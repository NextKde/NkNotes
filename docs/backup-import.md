# 完整备份与批量导入

2026-11-06。

## 完整备份

“设置 → 数据 → 完整备份”保存一个 `.nkbackup` 文件。它包含整个管理空间的笔记正文、分类文件夹、标签和属性、收藏及置顶状态、附件原件、历史版本、恢复草稿、导入记录、智能集合及最近删除。不包含外部 Markdown 原文件、窗口布局或系统外观设置。

备份通过 SQLite Online Backup API 获取一致快照，覆盖 WAL 中已提交内容；不会直接复制正在写入的数据库文件。临时快照完成后分块写入 QSaveFile，成功才替换目标。存储内部目录不能作为备份目标。建议将备份保存在其他磁盘，避免与原件一起丢失。

“设置 → 数据 → 恢复完整备份”会替换当前管理空间，不合并两边数据。界面先明确确认替换范围。当前编辑先完成保存，再检查选中的备份副本：应用标识、版本、数据库完整性、外键、必要表字段、附件路径与不支持的触发器／视图。检查不通过不替换当前空间。

恢复前自动生成一份 `.nkbackup`，位于管理空间旁的 `Backups` 目录。成功提示提供完整位置，可通过同一恢复入口取回恢复前内容。没有成功生成保护副本时，不继续恢复。数据库恢复由 SQLite Backup API 完成，失败时未完成的目标事务回滚。附件缓存刷新失败单独提示，数据库内的附件原件仍保留。

技术依据：[SQLite Backup API](https://www.sqlite.org/backup.html)。格式目前为应用标识与版本受校验的 SQLite 文件；不是 Markdown 导出的替代文件格式。

## 批量导入

导入仍需先预览来源、目标、数量、目录结构和重复策略。扫描、内容检查、准备和写入显示阶段及已处理数量。读取阶段可停止；确认导入后也可停止。操作在存储工作线程执行，取消使用线程间原子标记，不等待工作线程处理另一条排队命令。

每次只保留当前笔记正文和附件的读取内容，不把全部待导入正文缓存到准备清单。每篇笔记及附件作为一个保存点，每 50 篇提交一批；每批同时保存未完成导入记录。停止后保留已完成的笔记，报告剩余数量；再次选择同一来源，以默认“跳过重复”继续导入。当前已开始的一篇可能先完成再停止。

中途取消或单篇失败时，已导入笔记中指向尚未导入内容的链接可能暂不可用，报告会说明。正常完成后补齐空文件夹；取消时保留已经因成功笔记创建的目录。导入结果中的文件夹数量为本次实际新增数量。

提交后的搜索和列表更新仍沿用当前内存索引；SQLite 全文检索、百万级规模的资源控制和同步策略不在本轮范围。AI 索引未实现。
