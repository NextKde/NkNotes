# 文件授权、附件迁移与故障恢复

2026-11-13。适用于本次开发分支；验证状态见末尾。

## 文件选择与 Flatpak

Flatpak 内的导入文件、导入文件夹、外部 Markdown、附件、Markdown 导出目录、完整备份及 HTML/PDF 输出，统一使用 Qt Quick Dialogs 的系统文件对话框。原生安装继续使用应用内选择器。正式包沿用 `QT_QPA_PLATFORMTHEME=xdgdesktopportal`，不增加 home/host 文件系统权限。

保存时在建议文件名中提供扩展名，使用系统对话框返回的原始 URL。若最终名称缺少要求的扩展名，提示重新选择，不在授权后追加扩展名写到另一个位置。取消不会发起读写，过期对话框回调不完成新的请求。写文件仍使用 QSaveFile，禁止退化为直接覆盖。备份先在私有位置生成一致 SQLite 快照，再写入所选位置；恢复先复制所选文件到私有位置进行校验。

单个 Markdown 文件的授权不包含同目录的图片。收集带相对附件的笔记时，应选择“从文件夹收集”；无法读取的资源保留原链接并报告。Qt 可能在系统对话框服务不可用时回退到内部对话框，因此组件测试不能证明 portal 已工作，必须在正式运行时观察实际 FileChooser 请求。Qt 6.11 的 portal 实现还存在程序主动关闭不发送 Request.Close 的限制；应用会取消本地请求并忽略迟到结果，但系统窗口可能仍需用户关闭。

## 跨位置恢复附件

新附件使用相对、百分号编码的 URL。数据库中 `assets/<SHA-256>.<扩展名>` 对应的 BLOB 是权威内容；磁盘 assets 目录是可再生缓存。

旧正文中的绝对 `file:` / `nkasset:` 链接只提供附件身份：必须精确匹配当前数据库拥有的路径与摘要，才能读取当前空间的附件。旧磁盘位置不会被读取。当前缓存需通过目录范围、符号链接、大小及实际内容摘要检查；编辑器获得的是已校验字节。外部 Markdown 只使用自身目录范围，不沿用内部空间的旧路径映射。普通文件/目录链接与图片读取分开校验，不把图片的 32 MiB 限制套用到普通外部链接。Linux 目录遍历使用 O_PATH，允许读取经过可搜索但不可列出的父目录下的已知文件。

恢复不批量改写正文、历史、草稿及其摘要。历史正文保留的 `../assets/...` 在移动后按数据库身份定位；它不授予跨目录读取权限。创建副本、应用模板和 Markdown 导出时，按目标位置重写受支持的附件链接并保留 URL 查询与片段。Markdown 导出直接读取 BLOB，即使缓存缺失或被更改也可生成原附件。HTML 资源链接及未知附件保留原文并在导出完成窗口列出警告。

附件清理同时检查当前笔记、最近删除、历史、恢复草稿、模板及内存草稿中的引用，防止当前正文不再引用后提前回收仍可恢复的附件。

## 当前数据库无法打开时恢复

初始化失败后，启动页提供“从完整备份恢复”。在私有副本中检查现有数据库及侧车文件，避免校验过程修改故障现场。所选备份需通过应用标识、版本、完整性、外键、受控结构、路径与附件摘要校验。

预检查还会拒绝被普通文件占用的缓存目录及缺少 rowid 的不兼容历史表。正常打开时，附件缓存写入失败作为警告报告，不把已经打开的数据库误报为初始化失败；故障恢复的新空间则必须完整生成缓存后才能发布。

恢复先在同级 `Library-restored-<UUID>` 准备完整可打开空间及附件缓存，再通过稳定入口目录中的 `active-library.json` 发布新位置。原数据库、WAL、SHM 等文件保留，原锁文件 inode 不替换。下次启动仍从原入口读取活动位置，并同时保护入口与活动空间的实例锁。

发布前失败保留原活动位置；发布后若目录同步无法确认，会明确提示关闭后重开，并阻止继续写入，不声称切换未发生。若当前空间本来可正常打开，则继续使用已有恢复机制：先生成保护备份，再恢复所选内容。

## 外部文件保存失败

保存外部 Markdown 前，先在内部空间独立提交恢复草稿。外部文件发生冲突、删除或写入失败时，本地输入仍可从草稿恢复；冲突后的继续输入也会自动更新恢复草稿，不覆盖外部版本。

草稿提交失败时，界面明确显示仅在内存中保留，关闭仍受保护。迟到的旧修订回包不会把最新输入标记为已持久保存。外部写入成功但草稿清理失败时，保留新文件摘要并报告清理警告，避免下一次保存误判为外部冲突。
