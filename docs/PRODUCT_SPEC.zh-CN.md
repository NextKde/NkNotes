# macOS 27 风格 Markdown Notes 产品与实现说明

这是一个面向 NextKde 桌面环境的 Markdown 笔记应用规格，覆盖产品体验、macOS 27 风格界面、组件接入、编辑与存储架构、知识关联、迭代顺序和验收条件。工作名称暂用 NextNotes，正式名称待定。

产品基线：整体界面统一遵循 nextkdeAppDemo 的 macOS27 设计语言；正文以 Markdown 为基础，提供即时排版和源码编辑；通过悬浮格式操作和结构化内容提高编辑效率，通过双向链接组织笔记。Notion 与 Obsidian 提供功能思路，不引入它们的界面风格。

版本为需求基线 0.1，建立日期为 2026年11月4日。本文可作为后续插件对话和开发工作的共同上下文。除明确写为已确认的产品方向外，技术方案与尺寸均为初始提案，进入实现前应完成对应决策。

# 一 产品方向与范围

## 已确认的方向

- 整个应用采用 macOS 27 风格，包括窗口、导航、列表、编辑区、工具栏、菜单、设置和关联面板。
- 使用 nextkdeAppDemo 的共享组件及设计规范作为界面基础。
- 正文采用 Markdown，避免把 Apple Notes 的正文编辑体验直接照搬过来。
- 保留 Apple Notes 式顶部悬浮格式操作，并提供靠近当前编辑内容的操作入口。
- 吸收 Notion 的丰富格式与内容组织能力。
- 支持 Obsidian 式笔记链接、反向链接及关系浏览。
- 通过持续迭代完成，优先形成可以真实使用、可靠保存的完整流程。

## 初始产品取舍

初始目标为单用户、本地优先的桌面应用。文件可在应用外阅读和编辑；索引损坏不应导致正文丢失。默认不依赖网络。

首版不包含多人实时协作、账号系统、云同步服务、插件市场、完整关系数据库和任意多列页面布局。这些是后续评估项，不影响首版 Markdown 文件的可迁移性。

首版成功的标准是：用户能够持续创建、整理、编辑、搜索和关联真实笔记，退出重开后内容完整，使用过程中界面始终保持一致的 mac27 风格。

# 二 核心使用流程

| 场景 | 用户操作 | 预期结果 |
| --- | --- | --- |
| 快速记录 | 新建笔记并输入 | 编辑器立即获得焦点，内容自动保存，列表同步摘要 |
| 格式编辑 | 输入 Markdown 或使用工具栏 | 两种入口修改同一份文档，撤销顺序连续 |
| 结构插入 | 在适用位置输入斜杠 | 打开内容插入菜单，选择后在当前位置插入 |
| 知识连接 | 输入双左方括号并搜索 | 选择已有笔记，或明确创建缺失目标 |
| 查找内容 | 输入全局搜索词 | 展示标题和正文命中，打开后定位相应内容 |
| 回溯关系 | 打开关联检查器 | 查看当前笔记的出链、反向链接和标签 |
| 整理资料 | 移动或重命名笔记 | 保留内容，处理链接变化，失败时可以恢复 |
| 外部修改 | 使用其他编辑器修改文件 | 无本地未保存内容时重载；有冲突时保留双方版本 |

新建笔记默认进入正文编辑区。主文档自动保存；重命名、链接编辑等临时面板中的草稿只有明确提交才生效。

# 三 界面结构与响应布局

## 主窗口

默认采用文件夹侧栏、笔记列表、正文编辑区三栏结构。关联检查器作为右侧可开关的辅助区域，不持续压缩正文。较窄窗口逐级收起辅助区域，并保留明确的返回与展开入口。

初始设计参考宽度为 1120、高度为 740 逻辑像素，属于可调整提案。侧栏约 200至224，笔记列表约 260至300，正文使用剩余空间；阅读栏宽与窗口宽分离。实际最小尺寸根据可用布局决定，不能通过裁切控件强行满足。

支持调整栏宽并保存布局。恢复用户保存的窗口尺寸优先于初始建议。窗口缩小时，先关闭关联检查器，再允许隐藏文件夹侧栏；正文必须仍能有效编辑。

## 文件夹侧栏

包含全部笔记、收藏、最近删除，以及用户文件夹和标签入口。默认导航深度保持简洁；深层文件目录通过展开或路径提示表达。导航条目使用普通材质选中和悬停填充。文件夹和标签是不同维度：文件夹表示文件归属，标签允许跨文件夹组织。

侧栏可收起，搜索与新建等高频操作在收起后仍可通过快捷键或工具栏访问。

## 笔记列表

每行展示标题、时间、正文摘要及必要状态。置顶、收藏和保存失败有明确但克制的标记。提供最近修改等排序方式。首版优先列表视图，卡片或图库视图后续评估。

列表选择由笔记稳定标识维护，不能仅依赖行号；排序、搜索或自动保存后不丢失当前编辑对象。

## 正文与关联检查器

正文采用安静的普通背景，标题、段落、清单、代码和引用通过排版建立层级。长文档滚动位置与光标位置按笔记保存。

关联检查器分为出链、反向链接和标签。反向链接提供上下文摘要，点击可跳到来源。关系图是独立的关系浏览视图，可从当前笔记展开，不作为日常编辑的默认背景。

# 四 macOS 27 视觉与交互规范

mac27 在本项目中指 nextkdeAppDemo 所维护的 macOS27 设计语言与实现约定。该仓库的自定义尺寸与光学参数是项目约定，不能统称为 Apple 官方数值。需求冲突时，用户后续明确决定优先；共享组件接入遵循仓库 AGENTS.md 和相应专项规范。

| 区域 | 材质要求 |
| --- | --- |
| 正文与笔记列表 | 普通实体材质，保持阅读对比 |
| 文件夹侧栏 | 贴边整块普通面板，背景不透明度 0.95，前景不透明 |
| 侧栏搜索与操作控件 | 轻档液态，保留玻璃边缘 |
| 顶部浮动操作区 | 按内容滚动与覆盖关系使用共享液态方案 |
| 嵌入式格式栏 | 普通材质，避免每个控件都套玻璃 |
| 菜单和上下文面板 | 一层液态外壳，内部条目与状态填充为普通材质 |
| 独立模态确认 | LiquidDialog，内部实体控件 |
| 帮助提示 | KosToolTip |

顶部区域未覆盖滚动内容时与正文保持连贯；实际内容进入其下方时，按共享规范切换材质。不得增加额外悬浮卡片式标题栏，也不通过复制壁纸或正文边缘伪造背景。

全部界面使用 AppTheme 语义颜色和集中维护的应用令牌。Notes 黄色作为应用识别色的使用范围待设计决定，不能覆盖共享组件中已明确固定的主确认按钮颜色。

液态输入、搜索、按钮和选择器不额外增加蓝色焦点边框；键盘焦点、激活与无障碍行为必须保留。普通材质的焦点样式遵循语义令牌。

支持浅色、深色、跟随系统、减少透明效果和减少动画。透明度只作用于对应背景材质，文字、图标与交互前景保持清晰。

玻璃只能采样同一窗口内真实、独立的内容子树。采样源排除消费者、弹层和采样器本身。普通透明窗口不等于能够取得桌面纹理；不隐式接入 KWin 液态特效。

# 五 Markdown 编辑体验

## 文档模式

提供即时编辑和源码模式。即时编辑显示排版结果，当前光标附近按编辑需要暴露语法；源码模式显示原始 Markdown。只读阅读模式可在后续阶段增加。分屏预览不是默认工作流。

切换模式必须保留内容、选区、撤销语义与大致滚动位置；不能经由 HTML 往返转换导致源文件重排。无法精确映射光标时应采用可解释的邻近位置，不可跳回文首。

## 格式能力分层

| 阶段 | 能力 |
| --- | --- |
| 基础 | 段落、标题、加粗、斜体、删除线、引用、有序和无序列表、任务列表、链接、分隔线、围栏代码块 |
| 丰富内容 | 图片、附件、表格编辑、代码语言选择、列表缩进、块移动、折叠标题 |
| 知识扩展 | 双向链接、标题定位、标签、链接别名、反向链接 |
| 后续评估 | 数学公式、提示块、内容嵌入、块引用、数据库视图 |

普通 Markdown 和明确批准的扩展构成可支持的文件格式。折叠状态、光标和阅读位置等界面状态默认放入应用元数据，不污染正文。

未知语法、未识别的 front matter 字段、注释及用户排版应尽可能原样保留。格式操作只修改目标范围，避免全文件重新序列化。文件编码、换行与末尾换行策略需在编辑器原型阶段明确。

## 顶部格式工具栏

包含新建、撤销重做、段落样式、清单、插入、表格与更多操作；分组与可见项目随窗口宽度调整。格式操作必须读取当前选区并反映混合状态，无适用目标时给出正确禁用态。

按钮点击不能先清空正文选区。工具栏、快捷键、斜杠菜单和右键菜单调用同一组编辑命令。

## 选区工具条与斜杠菜单

文本选区工具条提供加粗、斜体、删除线、行内代码、链接等就近操作。不得遮住选中文字或输入法候选框；键盘用户可以完成同样操作，Escape 关闭。

斜杠菜单仅在适用的编辑上下文触发；代码块、链接地址和普通路径输入不应误触发。支持输入过滤、方向键选择、Enter 确认和 Escape 取消；确认后只替换对应触发范围。

## 编辑可靠性

中文输入法组合期间不得被实时解析、自动保存回写或工具栏状态更新打断。一次格式命令形成一次合理撤销步骤。支持多段选择、粘贴、拖放与链接点击时的编辑边界。

初版富文本粘贴默认转换为支持的 Markdown 子集，并提供纯文本粘贴。未知 HTML 内容不得静默丢失，应保留可读文字或提示处理方式。外部内容渲染不执行脚本，不自动加载远程资源。

# 六 知识关联与搜索

## 链接规则

支持双向链接语法的目标形式为 [[笔记]]，别名形式为 [[笔记|显示文字]]，标题定位形式为 [[笔记#标题]]。最终语法与路径转义细节在链接格式决策中冻结。

输入双左方括号后显示候选，优先当前上下文与最近使用项。目标不存在时显示未解析状态，并提供明确的新建操作；不因为光标经过而自动创建文件。

内部索引使用稳定标识，文件中的链接仍保持人可读、可迁移。标题同名时显示文件夹或相对路径，禁止任意选择第一个结果。

重命名和移动需要先计算受影响链接，保留原始别名，识别代码中的伪链接；批量更新失败时记录已完成项并提供恢复，不把多文件修改误称为单次原子保存。

## 反向链接与标签

反向链接由解析后的真实引用生成，展示来源笔记、相关标题和文本上下文。代码块、行内代码以及转义内容按语法规则排除。未链接提及可以后续增加，界面中与明确引用分开。

初版标签建议从 YAML front matter 的 tags 字段读取，提供统一编辑入口。正文井号标签是否支持、如何排除标题与代码，保留为决策项。

## 搜索

支持标题与正文全文搜索，按文件夹、标签和收藏筛选。结果展示上下文，选中后跳转并高亮。中文检索必须具备专门验收样例，不能仅以英文分词效果判断可用。

## 关系图

后续提供局部关系图，再评估全库关系图。节点代表笔记，边代表明确链接；未解析目标应可区分。支持选中节点预览、打开笔记、限制关系层数与标签筛选。布局算法和渲染不应阻塞正文输入。

# 七 文件存储与恢复方案

本节为初始架构提案。正文采用 UTF-8 Markdown 文件，附件独立存放；SQLite 用于可重建索引。文件和索引的职责分开，索引不作为正文唯一来源。

建议库目录包含用户笔记文件夹、assets 附件目录，以及 .nextnotes 应用元数据目录。应用不能扫描或修改未选择的其他目录。库本身位于同步盘时，也必须能够处理外部变更与冲突。

## 标识与元数据

笔记稳定 ID 建议保存于 front matter 的 namespaced 字段 nextnotes_id，复用已有 front matter 并保留未知字段；导入没有 ID 的笔记是否自动写入该字段，需先确定策略。复制文件导致 ID 重复时必须识别并显式处理，不能合并覆盖正文。

标题来源、文件名和一级标题的同步规则需要确定。初始建议使用 front matter title，缺失时取首个一级标题，再回退到文件名；UI 重命名应清楚说明修改哪些字段。

收藏、布局和最近打开等状态放入应用元数据。创建与修改时间的来源和时区处理单独定义，不能仅依赖同步盘可能变化的文件时间。

## 保存机制

输入后建议以约 700毫秒防抖保存；切换笔记、关闭窗口或退出时处理待保存内容。该时间是初始参数，后续依据实际体验调整。

使用同目录临时文件和安全替换完成单文件保存，保留失败前内容。写入前校验文件是否被外部修改。状态至少包含已修改、保存中、已保存、保存失败和冲突；失败时编辑内容仍留在内存与恢复机制中。

附件导入先完成持久化，再提交正文引用，失败时不留下指向缺失附件的链接。删除笔记先进入应用回收区，可恢复；附件清理独立执行，首版不自动永久删除可能仍被引用的文件。

## 外部修改与恢复

文件监听使用事件驱动并合并重复通知，区分自身写入和外部写入。当前笔记无未保存内容时可重载；有未保存内容时保留双方版本并提供比较或另存，禁止静默覆盖。

崩溃恢复草稿、历史版本和已保存正文属于不同层次。恢复记录应包含版本或内容摘要，避免把旧草稿覆盖到新的外部文件。磁盘满、权限不足、附件丢失、非法文件和索引损坏均需有明确处理路径。

首版不承诺跨设备同步正确性；同步盘兼容意味着识别并保留冲突，不意味着自动合并全部情况。

# 八 应用架构与组件接入

## 模块职责

| 模块 | 职责 |
| --- | --- |
| QML 界面 | 窗口、导航、列表、工具栏、菜单、设置与状态反馈 |
| EditorSession | 当前文档、选区、编辑命令、撤销重做和模式切换 |
| MarkdownEngine | 增量解析、语法范围、渲染映射、链接与标签提取 |
| NotesRepository | 文件读取、安全写入、移动重命名、附件与恢复 |
| NotesModel 和 FolderModel | 对 QML 暴露笔记及文件夹数据 |
| SearchIndex | 全文搜索、索引更新与重建 |
| LinkIndex | 出链、反向链接、未解析目标及关系数据 |
| WorkspaceState | 当前库、布局、最近笔记、光标和滚动位置 |

正文改动先进入统一编辑会话，再触发保存与增量索引。磁盘失败不会回滚用户刚输入的文字。耗时解析、搜索和文件工作应离开 UI 线程，并避免旧异步结果覆盖新版本。

## 编辑器实现决策

尚未决定使用原生 Qt 文档编辑方案，还是使用嵌入式编辑内核。不能把普通 KosTextArea 视作完整 Markdown 编辑器。

先做独立技术原型，比较中文输入法、即时排版、源码保真、选区映射、撤销、长文档、QML 工具栏桥接、依赖许可与部署成本。嵌入式方案也必须呈现统一的 mac27 外观，不能暴露一套不同风格的网页工具栏。

原型完成前不锁定第三方编辑库，也不为尚未批准的库建立业务依赖。

## 引入 Kos Ui

正式应用建议使用独立 Qt Quick 宿主。Quickshell 是现有 Demo 的宿主，不是新应用的必需依赖。

使用 Git 子模块固定 nextkdeAppDemo 的已选完整提交，在应用 CMake 中引入 third_party/nextkdeAppDemo/shared/qml，链接 Kos::Ui 与 Kos::UiPlugin，QML 使用 import Kos.Ui。开发时可提供显式本地路径覆盖，默认和发布构建使用固定依赖。不要复制共享组件形成应用分叉。

父工程需提供 Qt 6.8 或更新版本的 Core、Gui、Qml、Quick、QuickControls2 和 QuickDialogs2，运行时提供组件实际导入的 QML 模块，包括 Qt5Compat.GraphicalEffects 与 SVG 支持。最终依赖清单以选定提交源码为准。

组件仓库当前保留 GPL-3.0 许可证；应用的许可与分发方案在发布准备阶段明确，保留许可证与来源文件。

| 操作菜单 | LiquidPopover、LiquidPopoverItem | 具体动作 |
| 链接与上下文编辑 | LiquidContentPopover | 锚点、草稿与提交 |
| 确认 | LiquidDialog、LiquidDialogButton | 后果说明与业务处理 |
| 设置 | SettingsGroup、SettingsItem | 持久化与设置联动 |
| 提示与空态 | KosToolTip、KosEmptyState | 文案与恢复入口 |
| 真实背景采样 | LiquidBackdrop | 独立同窗源和捕获生命周期 |

KosApplicationWindow 内置 Ctrl+B 切换侧栏，会与正文加粗冲突。接入前应让侧栏快捷键可配置或使用自定义窗口骨架，保留 Ctrl+B 给编辑命令；不可同时触发两个操作。

KosSidebar 当前提供容器、宽度与展开动画，不自动完成设计文档规定的背景模糊。贴边布局使用 floating: false，实际材质另按共享规范组合。

KosTextArea 当前是主题化普通 TextArea，不包含所需的 Markdown 编辑内核。它可以用于小型文本表单，不据此宣称正文编辑能力完成。

VectorIcon 是否已覆盖笔记、链接、表格等动作需要逐项盘点；缺失图标通过共享矢量体系补齐，不用字体字符临时替代。

窗口控件不假定固定三个按钮，不猜位置，不轮询标题栏像素。任何平台适配保持在可移植组件外；接管未确认时保留客户端回退。

# 十 快捷键与可访问性

初始快捷键方案：Ctrl+N 新建笔记，Ctrl+S 立即请求保存，Ctrl+F 查找当前正文，Ctrl+Shift+F 全局搜索，Ctrl+B 加粗，Ctrl+I 斜体，Ctrl+K 插入或编辑链接。源码切换与侧栏开关使用不冲突的组合，最终在命令表统一确定。

所有快捷键集中注册，并根据焦点上下文启用；编辑区、搜索框和弹层不能相互抢占。跨平台修饰键映射与桌面保留快捷键在目标环境中验收。

图标操作提供可访问名称和适当提示，列表项暴露标题与状态。Tab 导航、方向键选择、Enter 激活、Escape 取消均可用。正文可调整字号，增强对比和减少动态不会降低基本功能可达性。

错误消息说明发生了什么、当前内容是否安全以及可以采取的下一步，不只显示内部异常文本。

# 十四 持续迭代方式

每轮迭代开始时先阅读本文的产品基线、当前状态和待决策项，再检查实际工作区及组件版本。用户的新决定更新相应正文，旧决定移入简短决策记录，不保留互相冲突的现行要求。

维护一份集中的命令表、Markdown 格式约定和组件差距清单；不在多个页面复制互相独立的规格。内容变长后可拆为子页面，并在此保留入口与当前结论。

本地文件当前作为规格基线。Pages 插件本轮连接失败，云端创建结果未确认；恢复连接后先检查是否已存在同名页面，再决定同步或创建，避免重复。手动通过插件继续更新文档；保存文档不等于运行开发任务或启用定时自动化，未来需要自动维护时再单独指定触发条件和范围。
