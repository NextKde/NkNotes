# 笔记整理操作与接口

本轮扩展日常笔记管理；沿用现有 Kos.Ui 组件，不另做视觉改版。

## 操作入口

- 笔记列表标题旁的“笔记列表操作”：多选、全选、置顶/取消置顶、收藏/取消收藏、复制、移动、最近删除及排序。
- Ctrl+点击切换单篇选择；Shift+点击选择连续范围；选择模式中有独立复选框。列表获得焦点后 Ctrl+A 全选、Ctrl+Space 切换当前项、Esc 结束多选。
- 右键笔记可对该篇或已选多篇执行整理；当前文档的“更多笔记操作”也提供入口。
- 排序支持修改时间、创建时间、标题，升序/降序；置顶始终在普通笔记之前。每个笔记库和筛选范围分别保存排序设置。收藏与置顶是独立状态，不写入正文。
- 文件夹右键或“当前文件夹操作”：新建子文件夹、移动／重命名非空文件夹、整体回收与恢复、删除空文件夹。

一次选择及操作上限 200 篇。选择范围以当前可见搜索/筛选结果为准，改变查询、文件夹或笔记库会清空选择。排序及保存不因行号变化丢失选择。

## 控制器接口

| 接口 | 参数/结果 |
| --- | --- |
| `organize(action, paths, folder)` | action 为 `pin/unpin/favorite/unfavorite/duplicate/move/trash`；paths 为库内相对路径；move 的 folder 为空表示根目录 |
| `batchReport` / `batchFinished` | `action, succeeded, failed, results`；每项带 `path, ok`，失败带 `error/message`，成功按操作带 `newPath/trashToken/unchanged` |
| `sortKey` | `modified/created/title`，切换时重新查询并拒绝过期搜索回包 |
| `sortAscending` | 排序方向；置顶优先级不随方向改变 |
| `manageFolder(operation, path, target)` | `renameFolder/removeFolder`；renameFolder 支持非空目录整体移动／改名，removeFolder 仅删除空目录；trashFolder 整体回收，restoreFolder(token) 恢复；新建继续使用 `createFolder` |

控制器先排空编辑器和待保存状态，再构建批量请求；当前文档使用刚保存后的基线摘要，避免列表尚未刷新时错误地引用旧摘要。批量期间阻止笔记切换/关闭越过操作边界，文件监听不把自己的移动、删除误认为外部冲突。删除当前文档成功后清空会话；移动成功后打开新路径。

## 存储接口与安全语义

Repository 的 `batch` 接收 `action, items, folder`。每个 item 必须带 `path/baseHash`；逐项验证路径、符号链接、真实文件和当前内容摘要，拒绝过期基线。同名目标不覆盖。同一请求重复路径不重复执行。

批量操作按项提交，**不承诺整批原子性**。部分失败时成功项保留成果，失败项留在原位并报告；删除复用现有可恢复回收协议，复制复用安全保存并生成新身份。原文的自定义 front matter 保留；复制不改变源文件。失败提示与保存失败分开，不把整理错误当成恢复草稿错误。

文件夹移动／改名会保留子目录、隐藏文件及普通附件，拒绝目标已存在、移动到自身子目录、符号链接及保留目录。整体删除使用 `trashFolder`，在 `.nextnotes/folder-trash` 中保留全部内容；恢复中心用 `restoreFolder(token)` 恢复到原路径，不覆盖同名目标。空目录仍可直接删除。

移动／改名会更新普通 Markdown 行内链接、图片与引用定义中的相对路径，同时更新其他笔记的入链；保留查询参数和标题片段。双链可以更新明确的路径或唯一文件名目标；同名歧义拒绝处理。代码和 front matter 不参与链接重写。HTML 链接目前保守拒绝；尚非覆盖任意 Markdown 扩展的通用解析器。

多文件更新不承诺瞬间原子可见。操作先保存 `.nextnotes/move.json` 的前后内容及路径记录，再按摘要校验写入；文件移动使用不覆盖目标的原语。中途失败保留记录并阻止后续写入，可用更多菜单“恢复未完成的移动操作”（`recoverMove()`）回退。恢复只接受与记录相符的内容，遇到外部修改停止，不覆盖外部版本。批量仍按项报告成功和失败；同一批中的后续笔记接受此前成功项造成的引用变化。

## 应用内链接导航

正文 Ctrl+点击普通 Markdown 链接，库内 `.md` 在当前窗口打开；其他附件沿用系统打开。支持标题文字及常用标题 slug 片段。`navigateBack()` / `navigateForward()` 对应更多菜单和 Alt+Left / Alt+Right，切换前先保存，读取失败不推进历史。历史按当前库维护，应用内移动时更新路径。双链编辑／补全及关联面板见下节知识组织。

## 回收站批量操作（2026-11-05）

侧栏的“最近删除”使用主窗口的列表和详情布局，统一列出笔记和文件夹，支持全选、恢复所选、永久删除所选和清空。Ctrl/Shift 多选、仅多选时显示的 16px 复选框、标题栏取消选择和无箭头右键菜单与普通笔记列表一致；普通点击退出多选并显示所选项目的原路径、删除时间及恢复操作。恢复中心单独保留恢复草稿和提交历史。清空只处理确认框中列出的快照；确认后新进入回收站的项目不在此次范围内。附件回收区、恢复草稿、独立提交历史不属于这个清空范围。

`recycle(action, items)` 接收 `restore/purge` 和恢复列表中的 `kind/token/fingerprint`；Repository 对应 `trashBatch`，返回逐项结果及成功／失败计数。恢复遇到同名或内容变化保留原项；删除前核对回收内容指纹和受限存储路径。文件夹永久删除使用不跟随符号链接的目录描述符遍历，逐文件核对本次审阅后的内容；删除未完成保留标记，可刷新后重试，不能把已部分删除的文件夹当作完整备份恢复。

VM 验证包含：混合笔记／文件夹批量恢复、同名部分失败、快照过期拒绝删除、目录删除、符号链接保护；真实窗口检查批量恢复、清空取消及确认后文件和记录清除。永久删除不是磁盘安全擦除，也不删除独立历史副本。


## 知识组织与高频记录（2026-11-05）

### 历史

保存前将旧内容存入 `.nextnotes/history/<稳定身份摘要>/`，打开历史面板时补入当前版本。内容 SHA-256 去重，每篇最多 50 个不同内容版本；重复内容复用最初记录时间，历史不是逐次操作日志。应用内改名／移动沿用稳定身份，历史仍可访问。历史只从启用此功能后记录，不补造过去版本。

历史面板并排展示所选版本和当前完整 Markdown；恢复前先排空当前输入，再将选中内容作为可撤销的源码编辑，复用正常自动保存和外部写入校验。不提供逐行差异着色、自动冲突合并或整库备份。历史快照、异常提交日志和回收站互相独立；清空回收站不会清空历史。

### 搜索、标签与智能文件夹

后台维护可重建的内存三字符子串倒排表，中文无需英文分词；短于三个字符时在内存文档中匹配。输入查询不会重新读取全部文件；保存、库扫描和文件监听刷新文档，未变化的内容摘要不重新建索引。启动首次扫描及显式刷新仍需要读库，提供“重建搜索索引”入口。索引不持久化为 SQLite，正文始终是数据来源。

搜索支持 `tag:工作`、`tag:"project alpha"`、`folder:项目`、`is:favorite`、`prop:status=done`；可组合多个过滤条件和一段正文／标题子串。含空格的过滤值用引号包围，例如 `prop:"project=alpha beta"`。此轮不是布尔表达式、模糊匹配或相关度排序搜索。保存当前查询和范围后，左侧智能文件夹入口按条件重新查找；通过保存搜索对话框可覆盖或删除同名规则。

标签来源为 front matter 的 `tags`（内联数组或列表）；简单属性支持顶层文本值。面板只改选中字段并保留其他 front matter。复杂映射、列表及 YAML 类型转换仍使用源码模式；不解析正文 `#标签`。智能文件夹与模板按库存入 `.nextnotes/state.json`，正文标签随 Markdown 文件迁移。

### 双链与反向链接

正文支持 `[[笔记]]`、`[[./笔记.md#标题|别名]]`；输入 `[[` 后按标题／路径筛选候选，用方向键、Enter 或鼠标选择，Esc 关闭。选择器生成明确相对路径，避免同名笔记碰撞；手写无路径目标有多个匹配时提示歧义。代码和转义括号不当作双链。源码模式保留原样编辑，不提供富文本候选弹层。

“链接与反向链接”提供笔记和标题目标选择、插入链接、反链来源及摘要、未解析出链提示。反链仅来自明确链接，不包括普通文字提及；普通 Markdown 链接和双链共用相对路径解析。现有轻量链接扫描器保留对 HTML 链接的保守处理，不声称覆盖全部 Markdown 扩展。Ctrl+点击沿用应用内跳转和导航历史。

### 模板和每日笔记

模板可手动编写或从已保存当前内容生成；从模板新建会生成独立身份，原模板中的 `nextnotes_id` 不复用。变量 `{{date}}` 为本地日期、`{{time}}` 为本地时分、`{{title}}` 为指定标题。可以覆盖或删除同名模板；模板名称不参与磁盘路径生成。

“打开今日笔记”使用名为“每日笔记”的模板，没有模板时使用日期标题。创建 `日记/YYYY-MM-DD.md`；已存在时直接打开，绝不重新套模板覆盖已有记录。不包含日历视图、周期任务或自动定时生成。

## 缺失双链与批量标签（2026-11-05）

Ctrl+点击缺失双链会显示创建目标的库内相对路径，确认“创建并打开”后先保存当前输入，再创建带独立身份的 Markdown 笔记。无目录的目标放在来源笔记所在目录；显式相对路径可创建库内子目录。越界、绝对路径、保留目录、符号链接和非法文件名拒绝创建。确认时再次扫描和解析目标，若已出现唯一目标则直接打开；存在同名歧义时停止，不任意选择或覆盖文件。取消不会创建文件。标题片段不会自动生成对应章节。

列表多选菜单提供“添加标签到所选笔记”“从所选笔记移除标签”，沿用每批最多 200 篇的范围。其他标签、正文和自定义 front matter 保留；新增标签去重，移除只删除指定标签。

更多菜单和列表菜单均提供“全库重命名标签”。预览按整个库计算，不受当前列表筛选影响；确认处理预览快照中的路径和内容摘要。重命名到已有标签时合并去重；预览后被外部修改、有待处理草稿或无法安全保存的文件跳过并显示逐项结果。整批不是原子事务，成功项保留，失败项可以处理后重试。每篇复用安全保存及历史记录；批内共享一次库扫描结果，结束时统一刷新索引，避免对每篇重复全库扫描。智能文件夹保存的是搜索文本，标签改名不会自动改写其中的条件。

实现入口：Repository `resolveWiki/createWiki`、`tagPlan/tagBatch`；控制器 `createMissingLink`、`editTags`、`previewTagRename/confirmTagRename`。原生窗口回归脚本为 `tests/KnowledgeManagementUi.py`，只运行于可丢弃 VM 笔记库。

### 万篇笔记与长文实测

2026-11-05，在 `kos-vm-dev`（4 vCPU、约 8 GB 内存、Qt 6.10.2）用可丢弃库测试。后台样例为 10000 篇约 0.5 KB 的带标签、双链笔记，加一篇 2132903 字节、16000 段的长文。下表是单次实测，不是跨硬件性能承诺。

| 项目 | 优化前 | 本轮结果 |
| --- | ---: | ---: |
| 首次扫描和建立索引 | 19.02 秒 | 10.72 秒 |
| 30 次中文索引查询合计 | 684 毫秒 | 650 毫秒 |
| 当前笔记反链查询（全库链接环） | 102.64 秒 | 91 毫秒 |
| 外部连续改写 1000 个文件到索引全部更新 | 8.52 秒 | 2.12 秒 |
| 一万行模型反转排序、保持持久索引 | 超过 80 秒后停止基线测试 | 35 毫秒 |
| 约 2 MB 长文富文本打开 | 18.20 秒 | 13.41 秒 |

后台最终样例峰值 RSS 约 268 MiB；等待后台操作期间，测试主线程 16 毫秒心跳最大间隔 33 毫秒。这只是 Repository 测试的事件循环数据，不能代替图形界面或 WebEngine 的输入延迟。

优化包含：维护文件名／标题到路径的查找表，避免反链逐条遍历全库；只更新变化的文件监听，监听扫描后复用索引查询；复用已编译的解析表达式；大列表使用一次布局变更并按身份映射持久索引；正文光标映射按文本片段缓存，不为每个字符分配位置项。超过 20 万字符时词数是估算值，状态栏显示“约”。

**长文响应尚未达标。** 上述规模优化后的富文本测试中，一次输入的直接事务约 48 毫秒，输入到保存约 2.72 秒，但编辑期间 Web 事件循环出现约 2.55 秒间隔。额外源码模式测试打开同一文件约 45.46 秒，编辑期间最大事件循环间隔约 37.53 秒；它不是超长文的可靠替代方案。两种模式都通过了落盘内容和撤销检查，不能因此将响应体验判为通过。没有自动将长文切到源码模式。

测试入口：手动运行 `notes-scale-validation` 验证后台规模，`notes-scale-validation --model` 验证万行排序及持久索引，`tests/ScaleEditorValidation.mjs` 验证已打开 VM 窗口中的长文。后者测量文档就绪与强制布局，不以后台窗口中可能暂停的动画帧回调作为结束条件；原生自动化跳过 Web 可访问性子树，避免遍历数万节点污染测时。报告位于 `output/scale-validation-2026-11-05/`。不加入常规自动测试流程，不在本机运行。

### 后续：长文打开优化（2026-11-05）

同一 VM、同一长文：正文打开第一轮为 7.98 秒，最终构建复测为 10.22 秒，相对此前 13.41 秒减少约 24%～40%。这是两次实测范围，不是稳定延迟承诺，也不是应用冷启动耗时。最终构建内部加载约 6.03 秒，其中 Markdown 解析与转换约 2.44 秒、编辑视图更新约 3.21 秒；端到端计时还包括原生导航、WebChannel 和后续布局。
